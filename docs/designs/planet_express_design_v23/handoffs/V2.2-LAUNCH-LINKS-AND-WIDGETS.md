# Handoff: v2.2 — launch links + container widgets

> **Shipped as v2.2.0. The code wins where they disagree.** The widget-label override below was narrowed during the build: see the four-part guard in the "Matched by image repo" bullet.

Builds on `V2.1-ABOVE-THE-FOLD.md`. Two additions that together **replace the homepage container**:

1. **Launch links:** every container with a Traefik route gets a `↗` that opens it in a new tab.
2. **Container widgets:** the container detail view shows live stats from the app's own API, fetched server-side.

**Visual reference:** `reference/Dashboard v2.2 - Launch Links and Widgets.dc.html`, with four sections: A drawer, B pills, C detail + widget gallery + states, D mobile.

## 1 · Launch links

### Data: one derived field per container

```python
# dashboard_data.py, built from the Traefik routers already collected for the routing matrix
"urls": [
    {"href": "https://sonarr.casalan.com", "zone": "lan"},
    {"href": "https://sonarr.casaalmida.com", "zone": "public"},
]
```

- Map router → container using the Docker provider's service label (`traefik.http.services.<svc>` ↔ compose service). This mapping already exists for the routing matrix.
- **Build a URL only from a simple `Host()` rule.** For `Host(a) || Host(b)`, emit one URL per host. For `PathPrefix`, append the path. For `HostRegexp` or anything unparseable, emit nothing. A missing link is better than a wrong one.
- Scheme comes from the router's entrypoint (`websecure` → https).
- `zone`: `lan` if the host is on the LAN domain (`casalan.com`) or the router is a `-lan` twin; otherwise `public`.
- **File-provider routers** (plex, unraid, opnsense, qbit, solar…) aren't tied to a container. They go under the Network tab's `internal / external` zone and a `hardware` group, never under a stack.
- Optional escape hatch in `config.yaml` (editable key) for services with no router at all:
  ```yaml
  links:
    - name: homeassistant
      href: http://192.168.1.20:8123
      zone: lan
  ```

**Default target: LAN when both exist.** Public is the second button.

### Where links appear

**A · Overview stack tiles.** Tiles stay as dots. Add `↗ n` (mono 9px, `#5fd6e8`) before the tally, where n is the number of launchable containers in the stack. Hide it when n = 0. Clicking the tile opens the **stack drawer**.

**Stack drawer** (new, 420px, slides in from the right over the disk column):
- Header: LED · stack name (Chakra 700 18px) · `n containers · n launchable · n/n online` · close ×.
- Filter: `ALL n` / `LAUNCHABLE n`.
- One row per container: `grid 10px / 1fr / auto`. LED · name (mono 11.5px) over host (mono 9.5px, dim). On the right: `LAN ↗` (cyan, primary), `WEB ↗` (neutral), `◉` (dashed green = has a widget).
- No-route containers show `— no route` in ghost grey and no buttons.
- Clicking the name opens container detail. The buttons are `<a target="_blank" rel="noopener">`.
- Footer legend: "No button means no Traefik route. ◉ means a live widget in the detail view."

**B · Network router pills.** The pill *is* the link.

| State | Treatment |
| --- | --- |
| default | Unchanged from v2.1. No arrow at rest, so the matrix stays calm. |
| hover / focus | `#35c5d8` border, cyan tint, name `#8fe6f5`, trailing `↗`. `title` = full host. |
| LAN twin | Split pill: the name part opens the public host, and a right segment `LAN ↗` (divider `rgba(53,197,216,.45)`) opens the LAN host. Replaces the v2.1 `+LAN` tag. |
| router down | Crit tint + `DOWN` tag, no `↗`. Clicking opens container detail, not the URL. |

**C · Container detail header.** `OPEN ↗` (cyan, LAN) + `WEB ↗` (neutral, public) sit right-aligned in the header. On mobile, `OPEN ↗` takes the primary slot in the bottom action bar next to `RESTART ⟳`.

## 2 · Container widgets

### Architecture

```
browser  ──GET /api/widget/<container>──▶  dashboard backend  ──native API──▶  app (Docker network)
         ◀────── {stats, rows, fetched_at} ─────                ◀───────────
```

- **The server fetches, the browser renders.** The backend calls the app on the internal Docker network and returns normalised JSON. **API keys stay on the host and never reach the page.**
- **Keys live in the host secrets file** — as built, `/etc/planetexpress-dashboard.env`, root-only. Deliberately **not** `/etc/planetexpress.env`, the core's own secrets file (`config.py:140`, `:152`). Never in `config.yaml`, and **not editable from the dashboard**. Same stance as sensitive config.
- **Read-only.** Each widget declares its GET paths. The fetcher refuses any non-GET call. This keeps faith with "nothing surfaces or runs a command without approval".
- **On demand, cached 30s.** Fetch when the detail view opens (or the drawer's ◉ is hovered, as a prefetch). Don't poll on every scan: 85 containers × 60s is a self-inflicted DDoS.
- **Timeout 3s** per call. On timeout, show the stale cached values dimmed plus the error state.
- **Matched by image repo.** `linuxserver/sonarr` → `sonarr`. A `planetexpress.widget=<name>` label may pick between widgets that already claim the image, and `planetexpress.widget=none` disables it. **It can never route a key to an image outside the matched set.** The guard is narrower than a plain override (as built, `planet_express/integrations/rpc.py:785-826`):
  1. A label **baked into the image** may only disable a widget, never pick one. Only a label on the *container*, which the operator wrote, can pick.
  2. A key goes only to an image that is the widget's own **by name and by registry digest**. Image names and labels are self-claimed; a digest from a trusted registry is not.
  3. A **local build has no digest and never gets a key.**
  4. Never across a **shared network namespace**, where the key would reach the owner's address instead of the vetted image.
- **A widget never changes container health.** An unreachable API is shown on the widget only, never on the LED, the tile or the Hull.

### Widget contract

```python
# widgets/sonarr.py
WIDGET = {
    "name": "sonarr",
    "match": ["linuxserver/sonarr", "hotio/sonarr"],
    "key": "SONARR_API_KEY",          # env var in the host secrets file; None if no auth
    "port": 8989,
    "get": ["/api/v3/queue", "/api/v3/wanted/missing", "/api/v3/series", "/api/v3/health"],
}

def summarise(responses) -> dict:
    return {
        "stats": [                      # 3–4 tiles, always
            {"k": "QUEUE",  "v": 3},
            {"k": "WANTED", "v": 12, "level": "warn"},
            {"k": "SERIES", "v": 214},
            {"k": "HEALTH", "v": "ok", "level": "ok"},
        ],
        "rows": [                       # optional, max 3
            {"title": "Severance · S02E08", "pct": 84},
        ],
        "rows_label": "DOWNLOADING",
        "line": None,                   # optional one-line summary
    }
```

The front end renders every widget from this one shape. **Adding a widget means adding a Python file, with no template change.**

### Detail view placement

Container detail order becomes: **header (with launch buttons) → health verdict → widget → vitals → logs (collapsed) → action bar**.

The widget sits second because once the container is known healthy, what the app is doing is the useful next fact. Vitals drop to a 3-up row (CPU · MEMORY · RESTARTS). Logs collapse by default when a widget is present.

### Widget frame

`.pe-panel` at 12px radius.
- Head: live LED (beacon 2.4s) · app name (Chakra 700 12px, .1em) · `via <api path> · <age>` · spacer · `READ-ONLY` pill.
- Stat wells: `repeat(3|4, 1fr)`, 8px gap, `#08101c` wells, label mono 9px, value Chakra 700 22px (19px in gallery/mobile). Colour follows `level`, default `--pe-ink`.
- Rows: `grid 1fr / 110px / 40px`, title · cyan 4px bar · %. Or on jellyfin, poster slot · title · meta.

### States

| State | Treatment |
| --- | --- |
| **loading** | Skeleton wells with labels already in place, shimmer. After the first load, refreshes are silent and keep the old values on screen. |
| **needs an API key** | Dashed amber frame. "Radarr supports a widget, but no key is configured. Add `widgets.radarr.api_key` to the host secrets file." Footnote: "It can't be set from the dashboard. Keys stay on the host." |
| **API didn't answer** | Crit left-border. "The container is healthy, but its API returned 401. The key may have been rotated." Stale values stay visible, dimmed, with `last good n ago`. |
| **no widget** | **Section left out entirely.** No empty box. |

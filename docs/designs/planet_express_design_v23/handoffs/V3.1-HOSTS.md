## What changes, and why
The shipped `/hosts` page (`templates/hosts.html`) renders in a **standalone shell**: `.pe-app > .pe-wrap > .pe-masthead` with no tab bar. Every other page (`templates/dashboard.html`) renders in the **dashboard shell**: `.scanline`, `.vignette`, `<header class="topbar">` (logo, brand, `<nav class="tabs">`, header-status, SCAN, LOG OUT), then `.body-grid > .main-col > .tab-panel.active`. Landing on Hosts therefore drops the operator out of the app: no tab bar, no scan state, no way back except the browser.

**V3.1 puts Hosts inside the dashboard shell.** Hosts stays its own route, as today (`<a class="tab" href="{{ url_for('hosts') }}">` in the nav). On `/hosts` that link takes `class="tab active"`.

## States: unchanged
`LivenessState = current|stale|unknown` (`planet_express/core/hosts.py:52`) plus the separate unconfigured row (`planet_express/application/multi_host.py`). Reason → badge mapping as in `templates/hosts.html` (NOT PERMITTED `⛨`, CLOCK UNUSABLE `◷`, NO CONTACT `⌁`). Current / Stale / Unknown (3 reasons) / Zero containers / Unconfigured behave as V2.5; "unreadable is not absent, absent is not zero" holds: missing field = `not reported`, unreadable host = `unreadable`, `containers == ()` = "No containers on this host".
- Stale: hero is the age, meters render at 35% opacity with no level fill, chips lose status, `.cryo-pod.stale` supplies the amber LED.
- Unconfigured name is untrusted text; Jinja autoescape, never `|safe`.

## Fields shown (only what `HostDetails` / `HostMetrics` carry)
Details: cores, threads, arch, kernel, os_name, cpu_model. Metrics: cpu/mem/disk %, used/total GiB, `load`, `temps`. Containers: name, status, health, updatable. **The first render showed SWAP and FAN rows; those fields are not in S1's types and are removed.**

2. **Link style for `OPEN ↗`**: the existing `.pe-link-out` (defined after line 582) can be reused as-is. The render uses an inline teal stand-in.
3. Optional: a `.cryo-pod` variant for state 4 is not needed.
Nothing else: every other class is in the sealed block or already defined.

## Known fragility in shipped code (not changed here)
Unknown reasons are derived by substring-matching `host.liveness.reason` in the template (`'not permitted'`, `'timestamp'`, …). A reworded reason silently falls through to NO CONTACT. Suggest an enum on `Liveness` and keep the template to a lookup.

# V2.5 · Other hosts (read-only fleet)

> **Design handoff, not built.** Reference render: `screens/Other Hosts.dc.html` (use the PREVIEW STATE switcher).
> Metrics and CPU models in the render are illustrative; only hostnames, core counts, architecture, OS, memory and container counts come from the brief. Where this and shipped code disagree, the code wins.

Builds on V2.4. A new **HOSTS** tab. Every host in beszel's hub except the one Planet Express runs on (`casamediaserver`, deliberately absent: it has its own card with controls, collected another way). **Read-only: no buttons, no actions.** Tab placement is a suggestion.

## Rule that governs everything
**Unreadable is not absent, and absent is not zero.** A value nobody could read never renders as `0`, blank, or a bare `—`.
- Field missing on an otherwise-live host → the words **`not reported`** in `.pe-value.none`. (Unraid's OS name today.)
- Whole host unreadable → the card says so, with a reason, and the value rows read **`unreadable`**.

## Page structure
1. `.pe-verdict` (always first). Orb: `✓` ok, `!` warn, `⚠` crit, `?` unknown.
   - all current → ok, "N OTHER HOSTS READING"
   - any stale/unknown → warn, "SOME HOSTS ARE NOT READING", detail gives the counts
   - **every** configured host unknown → `unknown`, "NOTHING CAN BE READ". The collector failure is said **once, here**; the cards underneath stay compact and deliberate.
   - tally chips: `ok` CURRENT · `warn` STALE · `warn` UNKNOWN (`crit` when all) · `info` NOT CONFIGURED
2. `.pe-panel` "OTHER HOSTS · BESZEL" with `.pe-chip.info` READ-ONLY and a `.pe-panel-note` naming the source.
3. `.pe-grid` with `--pe-track:370px` (set inline; wider than 300 because a host card carries three meters). One card per host, configured order, **unconfigured last**.
4. `.pe-dashed-footer` (outside any branch): "casamediaserver is not listed here…".

## The five states

| # | State | Card | Badge | Hero |
|---|---|---|---|---|
| 1 | Current | `.pe-card.ok` (or `.warn`/`.high`/`.crit` from the worst of CPU/mem/disk) | `ok` CURRENT | CPU % |
| 2 | Stale | `.pe-card.warn` | `warn` STALE · 14m | **the age** ("14m ago", label SINCE LAST READING) |
| 3 | Unknown | `.pe-card.none` + reason | per reason, below | none |
| 4 | Zero containers | state 1 or 2, container block swapped | CURRENT | CPU % |
| 5 | Unconfigured | `.pe-card.none` | plain `.pe-badge` NOT CONFIGURED | none |

**1 Current.** Reading order: head (LED, name, badge) → hero CPU → sub line (`2C / 2T · x86_64 · OS`) + `OPEN ↗` → three meters (CPU, MEMORY, DISK: label, value, `.pe-bar`) → readout (load 1·5·15, swap, temp max + sensor count, fan if any, OS, arch · kernel, CPU model, cores · threads) → `.pe-footnote` listing every sensor → containers block. Sensor map is demoted to the footnote: eight raw readings must not compete with the hero.

**2 Stale.** The age replaces CPU as the hero because age is the answer. All meters lose their colour fill (`.pe-bar-fill` with no level), all values go `.pe-value.dim`, chips go `.idle`, LED is `warn`, and a `.pe-footnote.warn` says nothing is live. A stale number cannot pass for a live one.

**3 Unknown.** Always renders (it is in config). Three **visibly different** reasons, each with its own badge, glyph in `.pe-sensor-dark`, bold one-line title, explanation, and a "Check:" footnote (description only, never a command):

| Reason | Badge | Glyph | Why it is distinct |
|---|---|---|---|
| Collector unreachable | `crit` NO CONTACT | `⌁` | Hard failure. |
| Account not permitted | `warn` NOT PERMITTED | `⛨` | Hub returned success and an empty list. Looks like "no hosts". Copy says so explicitly. |
| Unusable timestamp | `warn` CLOCK UNUSABLE | `◷` | Host reported; its age cannot be trusted. |

Rows: `CPU · MEM · DISK` → `unreadable`; `LAST GOOD READING`; `CONTAINERS` → `unreadable`. The config link still shows (`OPEN HOST UI ↗`), it comes from config, not the remote host.
**All hosts unknown (collector down)** → three state-3 cards under one `unknown` verdict. See the COLLECTOR DOWN preview.

**4 Zero containers.** Count reads `0` (`.pe-value.dim`) and the block says "No containers on this host. It runs none; that is normal here, not a failed read." No empty box, no failure colour. Contrast with state 3, where containers read `unreadable`.

**5 Unconfigured.** Visible, never ignored. Name only, in mono inside curly quotes, `title` carries the full string. **No link, no readings.** Note: "Known to the collector, not yet set up here." Footer: "name supplied by the remote host · shown as text only".
**The name is untrusted.** Render as text only (Jinja autoescape; never `|safe`, never in an attribute without escaping). The render includes a hostile `<script>` name to prove it.

## Containers block (states 1, 2, 4)
- Readout head: `CONTAINERS` + count; with unhealthy ones: `6 · 1 unhealthy` in `.pe-value.crit`.
- First **6** as `.pe-service-chips` / `.pe-chip-svc` + `.pe-dot-svc` (names are long and `SCREAMING_SNAKE_CASE`; `title` has name · status text · health). `.crit` for unhealthy, `.idle` when stale.
- "Update available" is a quiet `UPDATE` tag inside the chip in `--pe-ink-label`. No status colour: an update is not a fault.
- More than 6 → `.pe-rollup` "+79 more containers · expand" (85-container host in the render). Card height stays bounded whether a host has 0 or 85.
- Status text, image, CPU, memory, network and ports are in the data but **not on the card**; they belong in the expand view. Not designed here.

## Level mapping (proposed)
Meter/hero level from percent: <80 `ok`, ≥80 `warn`, ≥90 `high`, ≥95 `crit`. Four levels plus idle only. Cyan appears only on `OPEN ↗` links and READ-ONLY chip (navigation).

## New CSS needed
Add after line 582 of `static/cockpit.css`; do not touch the sealed block.
1. **`.pe-card.none.reasoned { opacity: 1 }`** (and border stays dashed). `.pe-card.none` is 62% opacity, which makes the reason text and "Check:" line fail 4.5:1. States 3 and 5 carry content that must be read. The render uses `style="opacity:1"` as a stand-in.
2. **`.pe-link-out`**: mono 10px, `.08em`, `var(--pe-accent-ink)`, no underline, hover `--pe-accent-hi`, for `OPEN ↗`. The render uses inline style plus a bare `a` rule in `<helmet>`.
Optional: `.pe-card-sub` wraps poorly at 370px with a long OS string; `overflow:hidden; text-overflow:ellipsis; white-space:nowrap; min-width:0` would fix it.

## Data the template needs (confirm with DATA-CONTRACT)
Per host: `state` (`current|stale|unknown|unconfigured`), `unknown_reason` (`unreachable|not_permitted|bad_timestamp`), `age_seconds`, `link` (config only), hardware fields each nullable, `temps` map, `fans`, `containers[]` (`name,image,status,health,cpu,mem,net,ports,update_available`). **A nullable field must stay `None`; never default to `0` or `""` in the collector.** Add a guard test: a not-permitted empty list must produce `unknown`, not an empty page.

## Out of scope
Controls of any kind, acting on remote hosts, the local host.

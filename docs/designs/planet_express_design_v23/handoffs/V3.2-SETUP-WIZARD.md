# V3.2 · Setup wizard (first-run, browser)

> Design handoff, not built. Reference render: `screens/Setup Wizard.dc.html` (DESIGN PREVIEW strip at the bottom switches story, Telegram, install and exposure states; **do not ship it**).
> Spec source: `docs/designs/installer-brief.md` (v3-next). Where this and shipped code disagree, the code wins. Vocabulary is `pe-*` (like login, approval and execution), because setup runs before the dashboard shell exists.

## Shape
One standalone page, resumable. `.pe-app > .pe-wrap`: masthead with setup-mode chips → optional exposure banner → two columns (progress rail, content panel) → dashed preview strip (design only). The columns are flex-wrap, rail `flex:1 1 230px; max-width:290px`, content `flex:999 1 440px`, so it stacks on a phone. Each screen is its own route/state so a reload lands on the same step.

## Crew avatars (new asset set, applies everywhere)
The nine portraits were inconsistent: Fry and Zapp are tight heads, Leela and Scruffy busts, Bender, Hermes, Amy and Zoidberg full or three-quarter figures. At 32–40px the figures were unreadable. **Standard: one head-and-shoulders crop, 256×256 PNG, transparent background, rendered as a circle.**
- Files: `assets/characters/futurama/avatar/{fry,leela,farnsworth,bender,hermes,amy,zoidberg,scruffy,zapp}.png`. Originals are untouched. PNG only (security rule).
- Sizes: **72px** in a screen header (with `box-shadow: 0 0 0 2px var(--pe-border-strong)` ring), **56px** in `.pe-attrib` and `.pe-hint`, **40px** minimum anywhere else. Update `.pe-attrib img` (40px) and `.pe-hint img` (32px) to match; the render sets 56px inline.
- Existing surfaces (Crew tab tiles, Overview Professor aside, incident rollup) should switch to the `avatar/` set so one character looks the same everywhere. The Crew tab's per-member ring colours stay.
- Crops were cut by eye from the source boxes; re-cut if a source changes.

## Setup mode (brief §7)
- Masthead chips: `.pe-chip.warn` "SETUP MODE · CLOSES IN mm:ss" and `.pe-chip.info` "LAN ONLY · addr". The countdown is the token's remaining life.
- **Exposed** state: `.pe-card.crit` banner "SETUP IS REACHABLE FROM OUTSIDE YOUR LAN". Next is disabled while it holds. The page says how to close it (Welcome screen, step 03: Ctrl-C in the terminal that printed the URL).
- Secrets: typed once, never echoed, masked in the plan (`••••`). Fields render as masked values, never the secret.

## States per screen
- **Scan check row:** ok `.pe-check.passed` · blocked `.pe-check.failed` · note (amber, see New CSS). Each row: label, detail, optional fix text, badge. "Overridable" checks keep Next enabled. Blocked: `RE-CHECK ⟳` button; copy says Planet Express guides, it does not perform (Docker install, pool creation).
- **Telegram:** idle → listening (`.pe-check.running`, spinner, 60s) → found (chat id masked `···4411`) → tested (VERIFIED) | failed (`.pe-check.failed`, says which cause is likeliest). Skip stays available and states the consequence.
- **Operator:** NOT VERIFIED → VERIFIED (shows recovery codes in `.pe-card.warn`) | CODE REJECTED (`.pe-totp.is-rejected`, `.pe-field.is-rejected`). Next disabled until verified.
- **Install:** running (`.pe-verdict.warn`, `.pe-bar-fill.warn`, active marker, caret in log) · failed (`.pe-verdict.crit`, failed marker, `.pe-output.crit`, `.pe-hint` with Bender: "NOTHING FURTHER WILL RUN", RETRY STEP / BACK TO PLAN) · done. A reload rebuilds the view from `step_*` events.
- **Plan row:** idx, title, target, risk badge (`R0–R3`), REVERSIBLE / NOT REVERSIBLE chip, caret. Expanded: why, `.pe-output` preview, "NEEDS ROOT" label.

## Stories (brief §4)
FRESH · MOS (blocked on no pool; Docker note; boot hooks step) · FRESH · UBUNTU (blocked on missing Docker) · ADOPT HOMELAB (observe-only; 15 stacks, +10 collapsed under "show all"; ingress stack cannot be MANAGE) · REPAIR / UNINSTALL (diff-only plan; uninstall plan keeps a snapshot and says which step is not reversible).

## Data contract (brief §6) → UI
`discover.checks[]{id,label,status,detail,fix,overridable}` → scan rows. `discover.storage.pools` → pool list. `discover.stacks` → stack rows (`forbidden_suggested` → default IGNORE). `plan.steps[]{id,kind,title,target,risk,reversible,preview,needs_root,depends_on}` → plan rows (group by `kind`). `plan.will_not_touch` → guarantees. `apply` events → step rail and log. `verify` (same check shape) → done screen.

## Questions to settle with Claude Code
1. **Command previews conflict.** The brief wants "file content or command visible"; the design system rule is that no shell command ever reaches the UI (`description` only, guard test). The render shows **file contents and descriptions only** (config.yaml, env file with masked values, unit-file note). Sudoers would also be shown as file content. Confirm raw commands stay out.
2. Setup mode token: is it in the URL, a cookie after first load, or both? The page assumes a countdown it can read.
3. The exposure probe: who runs it, and how often? The banner needs a `reachable_from_outside` flag.
4. Does `apply` stream over SSE or polling? The log region assumes append-only lines with a step id.
5. Recovery codes: confirm they exist. If not, drop that card and keep "another operator can re-enrol you".

## Security constraints honoured (do not redesign)
No SVG icons; no URL-valued `planetexpress.icon`; no widget-label key routing: not touched by the wizard. Secrets go to `/etc/planetexpress.env` and `/etc/planetexpress-dashboard.env` (root-only), never `config.yaml`, never the browser. On MOS those paths live on the persistent pool.

## New CSS needed
Add after line 582 of `static/cockpit.css`; do not touch the sealed block.
1. **`.pe-check.warn`**: `border:1px solid var(--pe-warn-line); background:var(--pe-well); opacity:1`. Today `.pe-check` has `passed / running / failed` only; scan notes are neither OK nor blocked. The render sets this inline. Cyan `running` is navigation colour, never status.
2. **`.pe-check.is-selected` / `.pe-check.is-clickable`**: the powers screen reuses `.pe-check.passed` as an "on" state and sets `cursor:pointer` inline. A real selected style would avoid overloading "passed".
3. **Optional**: `.pe-input` is a display `div` (letter-spaced). Real `<input>` and `<textarea>` need a styled variant (`.pe-input input`, focus ring from `--pe-accent`). The render shows masked values instead.

Everything else is existing: `pe-app pe-wrap pe-masthead pe-kicker pe-chip pe-badge pe-card pe-panel pe-tabbody pe-verdict pe-rail pe-marker pe-check pe-totp pe-field pe-input pe-steps pe-step pe-readout pe-bar pe-logwell pe-logline pe-output pe-hint pe-attrib pe-btn pe-led pe-footnote pe-value pe-label pe-spinner pe-split`.

## Out of scope

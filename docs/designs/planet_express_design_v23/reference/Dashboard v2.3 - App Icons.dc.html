E · APP ICONS · RECOGNISE BEFORE YOU READ

used everywhere a container is named
SOURCE · MATCHING

Icons come from selfh.st/icons (repo selfhst/icons), in PNG, WebP and SVG, with light and dark variants. They're matched by image name: linuxserver/sonarr → sonarr.png. A planetexpress.icon label overrides the match. The backend downloads each icon once and serves it locally, so the page never calls a CDN.

STATUS STAYS SEPARATE

The icon keeps its own colours. Health is a dot on its corner, so an orange Prowlarr logo never reads as a warning. For a down container the row still goes red, and the icon drops to 40% opacity.

SIZES · FALLBACK

Four sizes: 13 in router pills, 18 in widget headers, 28 in drawer rows, 40 in the detail header. With no match, the tile shows two letters in the same frame, so rows stay aligned. Overview stack tiles keep their dots: a stack isn't one app.

HOW WIDGETS WORK
  • The server fetches, the browser renders. The dashboard backend calls each app's native API on the Docker network and returns plain numbers. Keys stay on the host and never reach the page.
  • Read-only endpoints only. Each widget declares the GET paths it uses. Nothing a widget does can change an app.
  • Fetched when you open the detail view, not on every scan. Results are cached for 30s. 85 containers polled every 60s would be a self-inflicted DDoS.
  • Matched by image. linuxserver/sonarr → sonarr widget. You can override it with a planetexpress.widget label.
  • A widget never changes health. An API that doesn't answer is shown on the widget, not on the container LED.

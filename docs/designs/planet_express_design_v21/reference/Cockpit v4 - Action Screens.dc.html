BUILD NOTES

  • Everything maps to existing tokens. No new colours — fresh/valid green, warn amber, high orange, crit red, idle grey, cyan for navigation and in-flight work only.
  • Destructive actions are two-step. Restart opens a sheet naming the blast radius, what data is at risk, and who the action will be logged as. The sheet's confirm button becomes the busy state in place.
  • Approvals are attributed, not anonymous. Three operators means "who handled this" is the common question — approved/denied cards keep the portrait, the timestamp, and the denial reason instead of vanishing.
  • Fix steps are descriptions only. No step anywhere renders a shell command. The command-never-surfaces test stays green.
  • Verification is its own phase. Execution is not finished when commands exit — it's finished when the service answers. Passed/failed is a verification verdict, not an exit code.
  • Interrupted is not failed. Failed means "we know it broke and rolled back". Interrupted means "we don't know" — so it offers re-scan first and never auto-retries.
  • Countdowns pause during submission. A plan can't expire between tapping AUTHORISE and the server recording it.
  • Empty states name the last thing that happened rather than saying "nothing here" — on a 3-person system that's usually the information you actually wanted.

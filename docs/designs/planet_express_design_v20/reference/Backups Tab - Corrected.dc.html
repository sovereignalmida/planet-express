BACKUPS TAB — DESIGN HANDOFF

The v3 Backups tab renders the data it's given, but the data it's given is the wrong data, in the wrong order, with the loudest field being the one that means nothing. Below: what's wrong and why, the corrected design, and the exact backend changes it needs.

A · WHAT'S WRONG

7 faults · 4 need a backend change
F1 · BLOCKER UI ONLY

STATE is the loudest field and it means nothing

The pod leads with STATE, which is systemd ActiveState. Borg jobs are oneshot units fired by timers — between runs that is always inactive. A perfectly healthy backup reads as dead.

casa_hermes.py:56 already says so — "because state is 'inactive' — check result and last_run instead". The dashboard didn't get the memo.

F2 · BLOCKER NEEDS BACKEND

No next-run time, so you can't tell if the timer is armed

A disabled timer and a healthy idle job look identical. This is the single most load-bearing fact on the tab and it isn't collected.

Already solved elsewhere: casa_stackctl.check_backups() reads LastTriggerUSec + NextElapseUSecRealtime off the .timer unit. casa_leela.check_backups() — the one the dashboard uses — only shows the .service.

F3 · HIGH NEEDS BACKEND

last_run is a raw systemd string with no age

You get Sat 2026-07-25 03:10:42 UTC and have to do date arithmetic in your head. "How fresh is my backup" is the question the panel exists to answer.

casa_leela.py:340 → InactiveExitTimestamp, passed through untouched. Jinja can't parse that format; the age has to be computed in dashboard_data.py.

F4 · BLOCKER NEEDS BACKEND

A nine-day-old backup renders green

The pod's only alert condition is result != 'success'. A daily job that last succeeded nine days ago and hasn't fired since is, by that test, perfectly fine. Silent staleness is exactly how backups fail.

Fix: a freshness verdict derived from age vs. cadence, not from result alone.

F5 · HIGH NEEDS BACKEND

Certs are a table of raw notAfter strings

A cert expiring in 5 days and one expiring in 300 render identically — same colour, same weight, same row. The vault has one job: tell you which cert is about to take the site down.

casa_leela.py:452 emits expires as openssl's notAfter ("Aug 15 12:00:00 2026 GMT"). Needs days_left computed alongside it.

F6 · HIGH UI ONLY

Broken-cert rows shatter the table

When some certs parse and one doesn't, check_certs() appends an error dict with a full sentence stuffed into domain and no other keys. The template only inspects cert_list[0], so that row renders as a paragraph crammed in the DOMAIN column with ? in the other three.

casa_leela.py:479-484. Error rows need their own card treatment, not a table row.

F7 · MED UI ONLY

Two orphan panels, no verdict

The tab opens with two panel headers and no answer to "is my data safe." Every other tab leads with a verdict (FLEET STATUS, HULL DIAGNOSTICS). Also: the pending-plan footer only renders in the unavailable branch, so plan context vanishes the moment data arrives.

templates/dashboard.html:366-372 — {% if ctx.pending_plan %} nested inside the else.

D · BACKEND CHANGES REQUIRED

casa_leela.check_backups() fixes F2, F3, F4

Also query the .timer unit, not just the .service. casa_stackctl.check_backups() already does this — lift the two systemctl show properties across. Keep returning a dict keyed by daily/weekly so nothing downstream breaks.

# .service props as today, plus two off the .timer
result[key] = {
"state": props.get("ActiveState", "unknown"),
"result": props.get("Result", "unknown"),
"exit_code": props.get("ExecMainStatus", "?"),
"last_run": props.get("InactiveExitTimestamp", "n/a"),
+ "next_run": tmr.get("NextElapseUSecRealtime", "n/a"),
+ "last_trigger": tmr.get("LastTriggerUSec", "n/a"),
+ "cadence_hours": 24 if key == "daily" else 168,
}
# "state" stays in the payload but is demoted to a footnote in the UI
dashboard_data.summarize_system_and_backups() fixes F3, F4, F7

Jinja can't do date maths on systemd strings. Derive everything the UI needs here and pass it down pre-computed, one extra key per job plus one tab-level verdict.

# per job, added alongside the raw fields
"age_human": "14h", # or "9d 4h", "never"
"age_hours": 14.2,
"next_human": "in 9h 48m", # or "timer not armed"
"timer_armed": True,
"window_pct": 58, # age / cadence, capped at 100
"freshness": "fresh", # fresh | stale | overdue | failed
 
# tab-level, new key on the summary dict
"verdict": {
"level": "ok", # ok | warn | crit | unknown
"title": "DATA IS SAFE",
"detail": "Both borg jobs succeeded on schedule…",
}

freshness rules — fresh: age < 1.5× cadence and result == success · stale: age ≥ 1.5× cadence, or timer not armed · overdue: age ≥ 3× cadence · failed: result != success. Worst job wins the tab verdict.

casa_leela._parse_cert_file() fixes F5, F6

Parse notAfter once, at the source, and tag error rows explicitly instead of smuggling the message through domain.

return {
"domain": domain,
"sans": sans,
"resolver": path.stem, # label as SOURCE FILE in UI
"expires": end_str,
+ "days_left": (parsed_end - now).days,
+ "tier": "valid" | "renew_soon" | "expiring" | "expired",
}
 
# error rows — stop overwriting `domain` (casa_leela.py:481)
- e["domain"] = f"⚠ {e['error']}"
+ e["kind"] = "error" # rendered as its own card

tier thresholds — valid > 30d · renew_soon ≤ 30d · expiring ≤ 7d (LED pulses) · expired ≤ 0d.
